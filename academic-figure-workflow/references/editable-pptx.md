# 把 AI 图里的文字做成可编辑 PPTX

交付栅格图时只告诉用户：图里已有的文字可以换成 PPT 里的可编辑文本框。同一轮不组装。用户接受这张图，并明确要可编辑文字之后，才分类、再组装。对图不满意就先改图，不在拒收的图上盖字。

字体由清单传入，不预设某一套字体。默认只把文字做成可编辑；简单几何是例外，要单独通过检查才收。源 PNG 不修改。

## 安装

技能不打包这些库。空环境装一次：

```bash
python3 -m venv .venv && .venv/bin/pip install pillow python-pptx vtracer pymupdf
```

Debian / Ubuntu 的系统 Python 会拒绝直接 `pip install`。用上面的虚拟环境。脚本缺库时打印同一条命令后退出，不会自己安装。

## 三类

- **文字**：标题、标签、图例、公式、刻度说明。盖住旧字，放原生文本框。每个文本框对应原图里一段看得见的字，放在原位置；不新增原图没有的标签或句子，改文案是另外的编辑。每段要有 `font`，`font_size` 的单位是源像素（`1 px = 0.75 pt`）。没写字体，或字体未安装，就停，并列出 `fc-list` 的结果。
- **简单几何**：独立的直线、折线、箭头和引出线。裁框里只能有这条笔画和一种平的底色，四周留一圈底色；贴着字、边框、图标或别的笔画的不试。用 vtracer 描成 SVG，形状和颜色都对上原像素才收下。vtracer 会把抗锯齿的笔画描浅，真实 AI 图上试过的箭头都过不了颜色检查，这时留在底图。
- **画面**：边框、卡片和面板，人物、机器人、图标和器物，纹理、阴影，以及曲线、色带、散点、柱、热图。留在底图上，不描摹，也不用原生形状或规整矩形重画。

区域不要互相覆盖。

## 组装

```bash
python3 <workflow>/scripts/build_overlay.py manifest.json --out figure.pptx
```

自下而上：原 PNG、调用方遮罩、通过检查的几何遮罩、文本框、SVG。遮罩是无边框、无阴影的纯色块，颜色取所在位置的底色。源图每边至少 96 px，否则 PowerPoint 放不下一页。

要调整就改清单重建，不要手工往 PPTX 里加形状。python-pptx 新建的形状默认带主题投影，脚本会去掉，手加的不会。

遮罩矩形不会由脚本计算。`masks[].rect` 原样变成色块，只做取整；`texts[].rect` 是另一份，两者不必相同。遮罩贴着旧字墨迹，文本框往往更宽，用来放新字。旧字还露出来就加大这一块矩形，色块碰到图标或边框就缩小。

清单字段：`source_image`、`image_size`、`masks[]`、`texts[]`，以及可选的 `vectors[]`。`vectors[]` 的 `kind`（`line`、`arrow`、`leader` 等）只作标注。几何检查看三项：原笔画被盖住多少、多出来多少笔画、重合处颜色差的中位数。通过的 SVG 写到 `<输出名>_vectors/`。验收写到同名的 `.result.json`。未通过的几何不盖住，底图上的原笔画保留。

SVG 是路径的可编辑源。PPTX 里它是可移动、可缩放的 SVG 图片，并带 PNG 回退。要在 PowerPoint 里改节点时，用「转换为形状」。

真实图交付前用 LibreOffice 导出一页，并打开渲染结果看，不能只看清单、XML 或 `.result.json`。整页看过之后，再放大到原像素看每个遮罩和 SVG 附近。要看：遮罩有没有变成带阴影的框、色块是否和周围底色脱开、旧字是否残留、文字是否裁切、SVG 的颜色和粗细是否和原笔画一致、箭头方向有没有变。结构检查通过但页面上能看见这些问题，这一版就不能交付。

导出要用和脚本相同的字体环境，例如同一个 `FONTCONFIG_FILE`。LibreOffice 换了字体，渲染出来的页面不能当验收。

```bash
libreoffice --headless --convert-to pdf --outdir /tmp figure.pptx
```

```bash
python3 <workflow>/scripts/build_overlay.py --self-check
```
